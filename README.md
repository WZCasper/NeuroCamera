# NeuroCamera

Автоматическая нейрокоррекция изображения с веб-камеры в реальном времени: 15-секундная
Автонастройка (баланс белого → экспозиция лица → шумоподавление), которая одновременно
двигает реальные аппаратные регуляторы камеры (яркость, экспозиция, баланс белого и т.д. —
через тот же DirectShow-интерфейс, что использует диалог «Configure Video» в OBS) и применяет
лёгкую программную коррекцию поверх. Живой предпросмотр показывает итоговую картинку прямо в
приложении; при желании те же параметры коррекции можно одним кликом отправить в фильтр
«Цветокоррекция» источника камеры в OBS через встроенный OBS WebSocket-сервер — без плагинов
и без ручного ввода значений.

## Требования

- **Windows 10/11 (x64)** — WPF и DirectShow API из этого проекта работают только на Windows.
- **.NET 8 SDK** (`dotnet --version` должен показать 8.x) — https://dotnet.microsoft.com/download/dotnet/8.0
- Физическая веб-камера.
- Для отправки коррекции в OBS (необязательно): OBS Studio 28+ с включённым WebSocket-сервером
  (Инструменты → Настройки WebSocket-сервера → «Включить сервер WebSocket»). Без этого шага
  приложение полностью работает — живой предпросмотр, автонастройка, сохранение параметров
  между запусками — просто кнопка «Применить в OBS» не будет иметь смысла использовать.

## Сборка и запуск

```powershell
cd NeuroCamera
dotnet restore
dotnet build -c Release
dotnet run -c Release
```

Либо откройте `NeuroCamera/NeuroCamera.csproj` в Visual Studio 2022 (17.8+) и запустите
через F5 — там же будет доступен визуальный дизайнер XAML.

## Тесты

`NeuroCamera.Tests` — модульные тесты для всей логики, не зависящей от Windows/WPF/камеры
(цветовая LUT-таблица, аутентификация и маршрутизация запросов OBS WebSocket через
имитацию сервера, атомарное сохранение настроек, журнал сбоев, потокобезопасный переход
между сессиями захвата). Запускается как обычный проект xunit:

```powershell
cd NeuroCamera.Tests
dotnet test
```

## Как работает Автонастройка

Нажатие «Автонастройка» запускает 15-секундный цикл в три фазы (баланс белого → экспозиция
лица → шумоподавление). На каждом кадре измеряется реальная яркость и цветовой сдвиг лица
относительно фона, и эти же измерения одновременно:

1. двигают в реальном времени аппаратные регуляторы камеры (видно на ползунках в приложении
   и, что то же самое, в диалоге свойств камеры в OBS) — это то, что подстраивает саму камеру,
   а не картинку после захвата;
2. подпитывают более лёгкую программную коррекцию (баланс белого, гамма, контраст/яркость,
   опционально билатеральный шумоподавляющий фильтр) поверх того, что аппаратные регуляторы
   не смогли докомпенсировать.

Результат сохраняется на диск и восстанавливается автоматически при следующем запуске —
повторять автонастройку каждый раз не нужно.

## Применение коррекции в OBS

Кнопка «Применить в OBS» пересчитывает текущую программную коррекцию в эквивалентные значения
фильтра OBS «Цветокоррекция» и подключается к OBS по WebSocket (протокол obs-websocket v5,
встроен в OBS с версии 28). Приложение само определяет, что делать с фильтром на указанном
источнике: обновляет настройки, если фильтр уже существует, создаёт новый при отсутствии,
либо — если на источнике найден фильтр устаревшей версии — пересоздаёт его в текущем формате
на том же месте в списке фильтров. Чужой фильтр с тем же именем, но другого типа, никогда не
изменяется — приложение сообщит об этом и не тронет его.

## Структура проекта

| Файл | Назначение |
|---|---|
| `NeuroCamera.csproj` | Проект .NET 8 WPF, зависимости OpenCvSharp4 |
| `MainWindow.xaml(.cs)` | UI: выбор камеры, кнопка «Автонастройка», предпросмотр, ползунки, интеграция с OBS |
| `ViewModels/MainViewModel.cs` | MVVM-состояние экрана, маршалинг событий на UI-поток |
| `Engine/VideoEngine.cs` | Захват/обработка/рендер: сессии захвата через `SerialSessionRunner`, отдача кадров в превью через `LatestValueMailbox` |
| `Engine/SerialSessionRunner.cs` | Гарантирует, что две сессии захвата камеры никогда не работают одновременно, без блокировки вызывающего потока |
| `Engine/LatestValueMailbox.cs` | Однослотовый почтовый ящик «последнее значение побеждает» для передачи кадров в UI без накопления очереди |
| `Engine/CalibrationEngine.cs` | State machine автонастройки на 15 секунд (3 фазы по 5 секунд) |
| `Engine/ImageProcessor.cs` | Математика OpenCV: AWB, детекция лица, измерение яркости/шума |
| `Engine/FramePipelineMath.cs` | Чистая (без OpenCV) математика построения LUT-таблицы коррекции и масштабирования кадра под предпросмотр |
| `Engine/HardwareCameraController.cs` | Чтение/запись аппаратных свойств камеры (яркость, экспозиция и т.д.) через DirectShow |
| `Engine/ObsEquivalentCalculator.cs` | Пересчёт программной коррекции в значения фильтра «Цветокоррекция» OBS |
| `Engine/ObsWebSocketClient.cs` | Клиент протокола obs-websocket v5: подключение, аутентификация, применение фильтра |
| `Engine/SettingsStore.cs` | Атомарное сохранение/загрузка настроек и последней калибровки между запусками |
| `Common/CrashLog.cs` | Журнал необработанных исключений (`%AppData%\NeuroCamera\crash.log`) |
| `Common/MatImageConverter.cs` | Конвертация `Mat` → `BitmapSource` |
| `Interop/DirectShowInterop.cs` | Перечисление имён физических камер через DirectShow COM |
| `Interop/DirectShowCameraControl.cs` | P/Invoke-обёртки над `IAMVideoProcAmp`/`IAMCameraControl` |
| `Assets/haarcascade_frontalface_default.xml` | Официальный каскад Хаара из репозитория OpenCV |

## Честно о том, что проверено и как

Полная сборка WPF-приложения требует Windows — в среде, где велась эта работа, её нет, поэтому
`NeuroCamera.csproj` целиком (WPF + OpenCvSharp4) не собирался локально; это подтверждается
только сборкой в GitHub Actions. Но там, где было возможно, утверждения проверялись, а не
предполагались:

- Вся логика без прямых зависимостей от WPF/OpenCvSharp (`Engine/SerialSessionRunner.cs`,
  `Engine/LatestValueMailbox.cs`, `Engine/FramePipelineMath.cs`, `Engine/ObsWebSocketClient.cs`,
  `Engine/ObsEquivalentCalculator.cs`, `Engine/SettingsStore.cs`, `Common/CrashLog.cs`) собирается
  и покрыта тестами в `NeuroCamera.Tests`, которые реально выполняются в CI.
- Таблица цветокоррекции (`ColorLut`) сверена побайтово с результатом настоящего OpenCV
  (Python, `cv2.convertScaleAbs`/`cv2.LUT`/`cv2.addWeighted`) на сотнях сочетаний параметров —
  расхождений нет.
- Протокол obs-websocket v5 (рукопожатие, аутентификация, коды ошибок, поля запросов фильтров,
  идентификатор актуальной версии фильтра «Цветокоррекция») проверен по исходному коду
  проектов obs-studio и obs-websocket, а не по памяти или предположению; тесты гоняют клиента
  против имитации реального сервера OBS, включая обрыв соединения, неверный пароль, зависший
  сервер и посторонний сервис на порту.
- Файлы с WPF/OpenCvSharp кодом (`VideoEngine.cs`, `MainViewModel.cs`, `ImageProcessor.cs`,
  `App.xaml.cs`) проверены синтаксическим анализатором Roslyn (тот же парсер, что использует
  `csc`) — это ловит опечатки и несбалансированные конструкции, но не проверяет типы и
  сигнатуры API; это делает только полноценная сборка в GitHub Actions.

Если `dotnet build`/`dotnet test` выдаст ошибку — пришлите полный текст, будет исправлено.
